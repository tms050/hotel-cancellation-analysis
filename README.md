# Hotel Cancellation Analysis

Аналитический проект: исследование отмен бронирований в отелях на основе открытого датасета [Hotel Booking Demand](https://github.com/rfordatascience/tidytuesday/tree/master/data/2020/2020-02-11).

## Цель

Понять природу отмен бронирований: насколько велика проблема, кто и когда отменяет чаще, какие параметры влияют сильнее всего, какова оценка выручки под риском. На основе выводов — сформулировать практические рекомендации для отелей.

## Бизнес-вопросы

1. **Насколько велика проблема отмен?** — доля отмен, динамика по годам, распределение по отелям.
2. **Когда отменяют чаще?** — сезонность, `lead_time`, день недели.
3. **Кто отменяет чаще?** — тип клиента, страна, канал бронирования, рыночный сегмент.
4. **Какие параметры влияют на отмену сильнее всего?** — сравнение силы влияния признаков между собой.
5. **Какие сегменты клиентов наиболее надёжны?** — фокус на позитиве: кого стоит удерживать.
6. **Какова оценка выручки под риском из-за отмен?** — верхняя граница потерь с декомпозицией по сегментам.

Подробное описание бизнес-вопросов и требований — в [`docs/business_questions.md`](docs/business_questions.md).

## Методология

1. **Аудит данных** (`01`): пропуски, дубликаты, аномалии, приведение типов, формирование производных признаков.
2. **Общая статистика** (`02`): структура бронирований, сезонность, сравнение отелей.
3. **Анализ отмен** (`03`): проверка гипотез, ответы на бизнес-вопросы, оценка выручки под риском, рекомендации.

Ноутбуки выполняются последовательно. Ноутбуки 02 и 03 читают очищенный датасет, сформированный в 01, — логика очистки не дублируется.

## Статус

Проект в разработке. Текущий этап: **Общая статистика завершена, переход к анализу отмен**.

## Ограничения анализа

- Причины отмен в датасете **не указаны** — выявляются только паттерны и коррелирующие факторы. Гипотезы о причинах формулируются отдельно и помечаются как таковые.
- Оценка выручки под риском — **верхняя граница потерь**: часть отменённых номеров в реальности перепродаётся, но данных о повторных продажах в датасете нет.

## Итоги аудита качества данных

### Объём
- Исходный датасет: 119 390 строк, 32 столбца.
- После очистки: 119385 строк, 37 столбцов.

### Удалено
- `babies >= 9` - 2 записи.
- `children = 10` - 1 запись.
- `adr < 0` - 1 запись.
- `adr = 5400` - 1 запись.

### Заполнено
- `children` → 0
- `country` → "Unknown"
- `agent`, `company` → 0

### Дубликаты
- Найдено 31994 дублей. Решение: пометить, но не удалять.

### Производные признаки
- `total_nights` = stays_week_nights + stays_weekend_nights
- `total_guests` = adults + children + babies
- `total_revenue` = adr * total_nights
- `booking_date` = arrival_date - lead_time (дней)

## Общая статистика

**Датасет:** 119 385 броней, июль 2015 — август 2017 (26 месяцев; 2015 и 2017 неполные).

- **Отмены:** 37% всех броней. City Hotel — 42%, Resort Hotel — 28%.
- **Выручка от проживания** (только состоявшиеся брони): ~26 млн. Топ-10% броней дают 31.6% выручки.
- **Каналы:** 80% выручки идёт через TA/TO, 53% — через Online TA. Direct — самый надёжный канал (15% отмен), Groups — самый рискованный (61%).
- **Сезонность:** устойчивый пик весной (май — ядро сезона). Профиль воспроизводится между годами.
- **Разные бизнес-модели:** City — короткие дорогие брони с высоким риском отмены; Resort — длинные дешёвые с низким.
- **`meal`:** BB — 77% броней (базовый тариф). FB — 0.7% броней, но 60% отмен.

Детали и графики — в [`notebooks/02_general_stats.ipynb`](notebooks/02_general_stats.ipynb).
